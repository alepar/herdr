summary: Round-1 code findings are within-spec implementation and test gaps that fall into four clusters (session-final END/ACK teardown, on_leg_bytes partial-commit, saved-machine idle-timeout flag, test environment isolation/timing). No spec decision generates them, so the fix is four cluster-wide sweeps plus standalone fixes, not a redesign.
pattern: (1) Session-final control messages (END{client-gone}/END{server-eof} and the final ACK) are treated as one-shot, fire-and-forget sends at teardown: consumed-and-lost on leg death (local_bridge.rs:986 and its final-review twin), final ACK gated by the 200 ms ack_due timer (local_bridge.rs:1096), flush counted at the pipe and then SIGKILL (local_bridge.rs:1065), unbounded wait for the client writer (local_bridge.rs:1084/1086), keeper marking end_sent before the write lands (keeper.rs:568), and the resulting test flake (keeper.rs:1202/1195 plus the final-review twin, and the spec-notes "graceful quit final-ACK race"). The spec already says these are best-effort, ordered after ring bytes, re-sent "over the next leg when none is live", and that the keeper waits for the final ack, so the implementation is what diverges, not the design. (2) on_leg_bytes commits recv_offset before the whole buffer validates: session.rs:507, its missing test session.rs:1581, and the final-review twin. (3) The saved-machine resume command drops --idle-timeout-v1: mod.rs:153, ssh_leg.rs:649 (a test that pins the wrong behaviour), and the final-review twin. (4) Tests depend on host-shared state or wall-clock timing instead of isolated resources and causal events: attacher.rs:430, mosh_fallback.rs:156, mosh_harness.rs:479, mosh_harness.rs:276, local_bridge.rs:1899, local_bridge.rs:2036, mosh_resume.rs:118. keeper.rs:198, the spec post-implementation notes and the task-11 baseline are independent.
clusters:
- C1-session-final-teardown: r1 [Should-fix] src/mosh/local_bridge.rs:986, r1 [Must-fix] src/mosh/local_bridge.rs:970-988 — leg_dead never re-queues a consumed session-final END, r1 [Nit] src/mosh/local_bridge.rs:1096, r1 [Nit] src/mosh/local_bridge.rs:1065, r1 [Nit] src/mosh/local_bridge.rs:1084; src/mosh/local_bridge.rs:1086, r1 [Nit] src/mosh/remote/keeper.rs:568, r1 [Should-fix] src/mosh/remote/keeper.rs:1202; src/mosh/remote/keeper.rs:1195, r1 [Must-fix] src/mosh/remote/keeper.rs:1195 — server_eof_forwards_remaining_bytes_then_end flakes (final ACK not flushed) | rule: on both sides, treat a session-final END as retained session state, not a one-shot queue item. It stays pending until it is confirmed written to a live leg, is re-queued on every new leg until the session is removed, and is never marked sent before the write succeeds. A final ACK for the full delivered offset is sent unconditionally on END{server-eof}, bypassing the ack_due timer. Every graceful-teardown wait (client-writer drain, ssh stdin flush before kill) is bounded by the spec's 500 ms stop budget, and the ssh child gets stdin EOF and that bounded window to exit before SIGKILL. Audit every other END/ACK send site against the same rule.
