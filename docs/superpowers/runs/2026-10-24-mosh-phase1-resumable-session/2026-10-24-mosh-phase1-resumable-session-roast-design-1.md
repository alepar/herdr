  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: src/platform/unix_common.rs:506-516 joins the hashed name directly onto std::env::temp_dir() with a /tmp fallback and no 0700 subdirectory. Every hash input is public or guessable. Spec line 186 relies on mode 0600 and rule 7 (line 95) names the 0600 sockets as the security boundary. connect() on a unix socket does not check the file's owner, so 0600 protects only a socket the keeper itself bound. The attacher is "a pure byte pipe" (line 180) and forwards HELLO (token) and the whole session to whatever answers.   severity: Blocking by floor. Panel rated Should-fix because it needs a hostile co-tenant on the remote. - [Should-fix] Ring caps and drain policy: "Leg up: the keeper stops reading the server while the ring is full. That is today's backpressure." — Reading the server eagerly into a 16 MiB ring while the leg is up defeats the server's single-slot render coalescing and replaces today's small-pipe backpressure with up to 16 MiB of stale frames queued ahead of echo on slow links; the equivalence claim is false.
  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
  evidence: src/server/client_transport.rs:276 holds `render: Option<Vec<u8>>`; try_send_render (lines 320-329) returns TrySendError::Full when a render is pending, so coalescing happens only while the server's socket write blocks. Today the ssh pipe and TCP window block it within kernel-buffer sizes. Under spec lines 103-104 the keeper drains the server socket until 16 MiB is unacked, so every render is emitted and queued FIFO. At 1 Mbit/s, 16 MiB is about 134 s of backlog ahead of keystroke echo. Seats grepped the spec for latency/coalesc/stale/slow/window/pacing: no in-flight cap, no latency NFR, no tradeoff statement; adaptive pacing is deferred (line 254) but line 104 still asserts equivalence. Regression occurs on a healthy link, so Challenge 5 (fail safe) does not cover it.
  fix-shape hint: cap leg-up in-flight (unsent + unacked) bytes to a small window (for example 64-256 KiB) so the server writer blocks and coalesces as today; keep the 16 MiB cap for leg-down buffering only; reword line 104.

  verdict: confirmed (reproduce ✓ / refute ✗-survived / ground ✓)
