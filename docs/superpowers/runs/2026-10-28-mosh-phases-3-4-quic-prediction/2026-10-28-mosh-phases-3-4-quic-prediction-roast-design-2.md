- [Should-fix] §2 Ordering and gaps (lines 124-131: "overdue by more than `max(SRTT, 50 ms)` after a later one arrived"); §2 Streams (lines 119-121); RenderReorder Owns (line 312); RenderLane Owns (line 303); absent: any send-order or priority rule for render streams — The overdue-gap rule treats a render frame as missing until its stream completes, and nothing orders render-stream transmission. Under quinn's default fair round-robin scheduling of equal-priority streams, a large self-contained PaneSurface is regularly overtaken by the small chained frames sent after it, becomes "overdue" with no packet loss, and triggers a chained-frame drop plus a resync whose full frame the same race overtakes again.
  verdict: confirmed (reproduce ✓ / refute ✗-survived (CONFIRMed) / ground ✓) — unanimous Should-fix; external fact grounded by all three seats
  evidence: https://raw.githubusercontent.com/quinn-rs/quinn/main/quinn-proto/src/config/transport.rs (fetched by all three seats): `send_fairness: true` in TransportConfig::default(); doc comment "When enabled, connections schedule data from outgoing streams having the same priority in a round-robin fashion." 3b line 100: "Stream priority is the same as the session stream"; 3b line 170 defers only lane-versus-session priority, not ordering among render streams; the only reset rule is self-contained resets older, so a patch never resets the full frame ahead of it. 3b §3 counts arrival as a completed stream. Under round-robin a one-packet patch completes in one flight while a multi-packet surface needs several congestion-window rounds, exceeding max(SRTT, 50 ms) on a high-RTT link with no loss. Distinct from the iteration-1 rejections (loss-recovery timing; loss-driven livelock): this mechanism needs no loss and is sender scheduling. The 3b timing test (10 % loss, screen changes once per second) would not catch it.
  fix-shape hint: pin render-stream send order (send_fairness false, or higher priority for older render streams), or measure "overdue" from header arrival rather than stream completion; run the finding's spike (0 % loss flood, count overdue-declared gaps) in the UdpRelay harness.
